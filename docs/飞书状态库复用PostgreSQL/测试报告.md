## 覆盖的行为

- 正常 PG 事务使用提交／回滚，不执行 SQLite 的 BEGIN IMMEDIATE。
- 启动检查采集表和列，不自动建表；缺表安全提示由单元测试覆盖。
- 真实临时 PG 中，采集去重、重新打开状态库恢复、回执 503 重试不重复追加通过。
- 删除原文后旧事件不会恢复文件，新消息可重新创建文档。
- SQLite 导入源只读，有积压时拒绝；完成后成功导入，重复导入跳过已有记录，旧消息继续去重。
- 内置／外部 PG Compose 采集都等待 migrate；内置连接 db:5432。
- config 只读与 data 可写挂载正确，采集独立于 HTTP 进程。

## 剩余人工验收

如果已经在本次 PG 切换后完成以下验证，不必重复；切换前的 SQLite 验收不能代替这一步。
只保留一个采集实例，本地执行：

```bash
uv run python -m app.feishu_cli status
uv run python -m app.feishu_cli collect
```

collect 是常驻命令。保持终端运行，在对应飞书群／私聊发送一条文本，例如“PG 采集验收”。
预期：data/my-inspiration/pending.md 追加一次原文、时间和来源，飞书消息收到 OK 表情回执。
另一终端执行：

```bash
uv run python -m app.feishu_cli status
uv run python -m app.feishu_cli logs --role collector --lines 100
```

预期 pending_messages、failed_messages、pending_receipts、failed_receipts 全部为 0，
日志没有持续连接、数据库或写入错误。不要另外启动一个 collect 来查询状态。

如果要在部署机验收，先按[PG 操作手册](操作手册.md)备份、迁移、更新采集容器；
停止同一机器人的本地实例，再从容器查询 status／logs 并发送一条真实飞书消息。
