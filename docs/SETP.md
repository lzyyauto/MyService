# 需求设计与实施流程

每项新需求在 `docs/<需求名称>/` 下维护文档，并依次完成以下阶段：

1. **现状**：说明目标、范围、当前问题和不能破坏的行为。
2. **设计**：给出最小可行方案、目录或接口变化、兼容策略与风险。
3. **实施**：按设计修改代码，保留用户已有数据和无关改动。
4. **验证**：至少执行语法检查、自动化测试，以及与改动相关的专项检查。
5. **交付**：记录最终结构、变更理由、已知限制和回退方式，并更新 `AGENTS.md`。

若设计与实现有偏差，最终文档必须说明偏差原因。涉及既有数据库迁移、密钥、用户数据或外部服务写入时，应优先采用兼容、可逆的做法。
