## 1. 需求与工作流程

默认接收机器人收到的所有用户私聊／群聊文本，不要求 @，不限制用户。按原始消息时间保存
完整北京时间、发送者、会话 ID 和内容。每个流程默认只有一份待处理 Markdown；可选按来源路径模板拆实例。
每天北京时间 01:00，把非空文档全文交给配置的 OpenAI 兼容服务与提示词；结果保存为独立 Markdown，
按配置发给指定群／用户。用户手动删除输入后不再提交；新消息创建新批次。

```text
飞书应用长连接 → 来源目录 → 路由 → 持久化收件箱 → 输入 Markdown → OK 回执
                                    ↓
每天 01:00／手动执行 → 输入存在检查 → 固定快照 → 共享 AI 客户端
                                               ↓
                               结果 Markdown → 可恢复的飞书发送
```

相同输入留着不删，下一天可以再次处理；手动 process 可重跑。失败 retry 恢复同一任务阶段，
已生成结果的保存／发送重试不会再次调用 AI。没有输入、空白或失效批次会跳过／取消。
正在请求 AI 时可以继续采集，本次只处理先前读取的快照；已经发出的请求无法撤回。

## 2. 代码结构与运行边界

| 模块 | 职责 |
|---|---|
| app/services/ai/ | 可独立复用的 OpenAI 兼容文本客户端：模型／Base URL／参数／密钥引用／超时／响应校验 |
| app/services/feishu/config.py | 受校验 TOML、模板路径、提示词热读取、原子替换配置 |
| app/services/feishu/events.py、transport.py | 事件解析／路由与飞书 token／回执／发送 |
| app/services/feishu/store.py、collection.py、files.py | 来源目录、持久化去重与队列、文件锁、追加恢复、原子结果保存 |
| app/services/feishu/processing.py | 每日任务、固定快照、租约／领取者校验、阶段恢复与有限重试 |
| app/services/feishu/observability.py | 按时间和容量约束的文件日志、错误抑制 |
| app/workers/feishu_gateway.py | 采集角色，单独管理多个应用连接与子进程 |
| app/workers/inspiration_processing.py | 独立调度／整理角色 |
| app/feishu_cli.py | 本地／容器通用命令：查询来源、发现、状态、日志、模拟、手动整理与重试 |

FastAPI 不导入／启动这些 worker，不新增业务 HTTP 路由。复用同一后端镜像，
按运行角色分进程；睡眠、运动、Notion 业务保持原入口。废弃 app/utils/ai_client.py 不启用。
旧 app.workers.feishu_inspiration 在 FEISHU_CONFIG_PATH 留空时兼容旧采集；设置后转交新版。
新版生产数据表由 Alembic 创建，不由 FastAPI create_all 抢先创建。

## 3. 配置与扩展

实际模板：[`config/feishu.example.toml`](../../config/feishu.example.toml)。
复制到未跟踪的 config/feishu.toml；真实密钥仅通过环境变量引用。

- apps：多个机器人、应用别名、凭证变量引用、飞书 API 前缀、默认流程。
- routes：按会话／会话类型分流，可选 require_at、allowed_sender_ids；默认接受所有用户。
- pipelines：处理器、原文路径、AI profile／提示词／每日时刻、结果路径、发送目的地。
- ai_profiles：全项目可复用的模型、Base URL、参数、预算和超时。
- runtime／observability：状态库、轮询重试、日志限制、来源目录保留与限时发现。

第一版处理器为 markdown_collect；增加群和复用流程只改配置，新业务处理器需要写代码并注册。
新增业务的完整步骤与重启判断见[扩展指南](扩展指南.md)：配置扩展自动热加载，
修改 .env／runtime／日志目录需要重启相关角色，代码扩展需要重新启动或发布镜像。
输入支持 app_id／chat_id／pipeline_id 模板；输出另支持 date／run_id。
共享来源合并进同一流程；按来源模板拆开后，每个实例只有一份活动输入。
固定输出路径先保留 .history 版本，再原子替换；用户原文、结果和备份不会按日志策略清理。

TOML 和提示词按修改检测，在消息／后台轮询时读取，默认约一秒。整份校验失败继续使用上个有效版本。
路由、模型、提示词、发送目的地等在下一事件／新任务生效；已有任务保持提交时的非敏感配置。
新增／删除应用或凭证引用变更只重建对应应用连接；.env 实际值变更需重启。
runtime 全部字段与日志目录变更需重启，避免状态库、角色锁和清理目录分裂。

## 4. 可观测性与来源 ID

默认不逐条打印完整机器人信息。sources 从状态库查询会话及发送者 ID；
新会话只提示一次，详细发现模式默认十分钟自动到期，每分钟最多六十条，重启不会续期。
原文与密钥不写入来源／任务诊断日志；INFO 只记录生命周期、任务、错误及有活动的五分钟汇总。

来源目录默认保留九十天、最多一万条。正式日志按角色目录隔离：默认七天、每文件 10 MB、
每角色总量 100 MB；启动、写入及每小时维护。容量上限可能提前淘汰旧文件。
两个 Docker 角色用 none 日志驱动，查询正式文件日志，不重复保存 Docker stdout。

具体 ID 获取、字段与 TOML 对应关系、容器查询命令均见[操作手册](操作手册.md#4-来源清单如何获取正确-id)。

## 5. 持久化与恢复边界

迁移 20261002_feishu 新增 feishu_sources／streams／messages／runs／controls 五张表，
不修改既有业务表及已发布迁移。来源、去重与任务状态用 PostgreSQL；本地明确选择的隔离 SQLite
只服务无 Docker 开发。SQLite 初始化不导入整个应用，也不创建睡眠／运动等生产表。

消息先持久化，再落盘，最后回执；已落盘正文从队列表清除，保留消息 ID 去重。
文件内批次／消息标识用于删除识别与半条追加恢复；AI 输入移除内部标识。
成功后清除任务快照与临时结果正文；未提交的失效批次／超过七天快照按维护清除，
已终结任务元数据九十天后清理。已经生成但发送失败的结果保留至恢复完成。

当日可补错过的调度，不追补所有历史日期；01:00 后新建的批次不补当天任务。
热调整执行时刻到已过时间不立即补跑，可显式手动执行。
生产迁移前需备份并核对 alembic current；空库验证不能代表历史生产库升级成功。
发送使用稳定 uuid，但服务端去重有效期之外仍可能重复；外部响应已成功而本地未记录的崩溃窗口
也可能重复调用 AI，不承诺外部调用绝对恰好一次。
