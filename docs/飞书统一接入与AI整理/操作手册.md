# 飞书接入与 AI 整理操作手册

> **历史文档，已停止实施。** 2026-10-02 按新需求撤回 AI 整理、每日调度与结果投递。
> 下文保留此前设计，仅供追溯，命令和配置不适用于当前版本。
> 当前运行、来源 ID 查询和扩展请用[纯采集操作手册](../飞书采集职责简化/操作手册.md)；
> 决定见[职责简化说明](../飞书采集职责简化/README.md)。

适用：Linux／macOS、Python 3.11；本地先验证，Docker 是最后一步。
配置字段以 [`config/feishu.example.toml`](../../config/feishu.example.toml) 为准。
不要把 `.env` 当 shell 脚本执行；CLI 会读取配置根目录的 `.env`，已有进程环境变量优先。

## 1. 不用 Docker、凭证或真实服务，先跑完整演示

```bash
cd /Users/zingliu/Code/my-service
uv sync --locked
uv run python scripts/feishu_local_demo.py
```

预期输出 JSON：来源查询成功、重启去重成功、发送重试没有重复调用 AI、删除原文后跳过、
新消息开启新批次。演示使用临时目录、隔离 SQLite 和本机 HTTP 替身，退出即清理。
演示故意让第一次结果投递返回 503，验证恢复；随后 `ok: true` 才表示闭环通过。
不会读取用户灵感，不连接真实飞书或 AI；这也不等于验证了生产 PostgreSQL 或 WebSocket。

## 2. 建立自己的隔离开发环境

以下命令在仓库根目录运行。仅首次复制，不覆盖已有配置：

```bash
test -f config/feishu.toml || cp config/feishu.example.toml config/feishu.toml
export FEISHU_CONFIG_PATH=config/feishu.toml
export FEISHU_STATE_DATABASE_URL="sqlite:///$(pwd)/data/feishu-dev/state.sqlite3"
uv run python -m app.feishu_cli validate
uv run python -m app.feishu_cli init-local
uv run python -m app.feishu_cli simulate --app personal --text '明天试着把项目拆成几个小步骤'
uv run python -m app.feishu_cli sources
uv run python -m app.feishu_cli status
uv run python -m app.feishu_cli process inspiration
```

预期：`validate` 为 `valid: true`；`init-local` 显示隔离 SQLite；模拟消息生成输入 Markdown；
`process` 显示 `execute: false`、`network_requests: 0`。示例默认关闭 AI，模型与地址是占位值。
模拟消息 ID 以本地应用身份写入，不能当作真实飞书 ID 配置回传。
`simulate` 拒绝 PostgreSQL；`init-local` 不创建生产表。

需要完全分离开发原文／结果时，在 TOML 中修改 `input_path`、`output.path`、`log_dir` 到
`data/feishu-dev/` 下。`root_dir = ".."` 相对 TOML 所在目录，其他相对路径都基于这个根目录。
进程使用的根目录和日志目录不能在运行中修改；停止并重启后才生效。

## 3. 配置真实采集与 AI

将飞书凭证、AI 密钥放入根目录 `.env`，或通过进程环境提供：

```dotenv
FEISHU_CONFIG_PATH=config/feishu.toml
FEISHU_APP_ID=填写实际应用ID
FEISHU_APP_SECRET=填写实际应用密钥
COLLECTION_AI_API_KEY=填写实际AI密钥
```

若使用 `.env` 设置 SQLite，填写绝对路径，例如
`FEISHU_STATE_DATABASE_URL=sqlite:////Users/zingliu/Code/my-service/data/feishu-dev/state.sqlite3`。
多个终端必须使用相同状态库与 TOML；第二个终端也要导出变量，或统一写进 `.env`。
更改 `.env` 后重启进程：热读取针对 TOML 和提示词，不针对 `.env`。
特别注意：在采集终端执行 export，不会改变另一个整理终端的环境；整理进程可能仍连接原 PostgreSQL。
如果看到 `state_schema_missing`／SQLSTATE `42P01`，先核对状态库选择。隔离 SQLite 用 init-local，
现有 PostgreSQL 必须先备份并检查迁移，再执行新迁移；不要把两种初始化方式混用。

TOML 中修改：

```toml
[ai_profiles.daily]
provider = "openai_compatible"
base_url = "https://你的服务地址/v1"
model = "你的模型名"
api_key_env = "COLLECTION_AI_API_KEY"
timeout_seconds = 120
max_input_bytes = 500000
```

Base URL 填服务 API 前缀，程序追加 `/chat/completions`。服务要支持 `messages`、
非流式响应及 `choices[0].message.content`。`parameters` 可放服务支持的温度等字段，
不能覆盖 `model`、`messages`、`stream` 或认证。共享客户端位于 `app/services/ai/`，
后续功能可以直接复用，不依赖飞书、文件或定时器。

在已有的 `[pipelines.ai]` 中设置 `enabled = true`，保留：

```toml
profile = "daily"
prompt_path = "config/prompts/inspiration.md"
daily_time = "01:00"
timezone = "Asia/Shanghai"
```

输入和结果路径分别由已有流程的 `input_path`、`[pipelines.output].path` 设置。
可使用绝对路径，本地进程必须有写权限；Docker 中必须是挂载进去的容器路径。
推荐结果路径包含 `{date}-{run_id}`，手动重跑也不会覆盖。
固定结果文件路径会把旧版本移入同目录 `.history/`；原文、结果和历史版本由用户自行管理，
日志保留策略不会删除它们。

启动采集与整理，各占一个终端：

```bash
uv run python -m app.feishu_cli collect
```

```bash
uv run python -m app.feishu_cli worker
```

先只启动采集即可获取来源 ID；接收并保存文本后添加 OK 表情回执。
默认群聊和私聊都接收，不要求 @，不限制用户；非文本只更新来源，不写入原文。
机器人和系统消息不参与采集，避免处理自己发送的结果。
每个运行角色只启动一份；多个应用由采集角色分别管理连接。用 Ctrl+C 停止本地进程。

## 4. 来源清单：如何获取正确 ID

推荐顺序：启动 `collect` → 在目标群发一条文本，或私聊机器人 → 查询来源清单。
清单只包含应用实际收到过的来源，不是租户通讯录，也不能列出机器人没收到消息的所有群。

```bash
# 查看全部来源；按最近观察时间排序
uv run python -m app.feishu_cli sources
# personal 是 TOML 中应用的别名
uv run python -m app.feishu_cli sources --app personal --kind group
uv run python -m app.feishu_cli sources --app personal --kind p2p
# 翻页
uv run python -m app.feishu_cli sources --app personal --limit 100 --offset 100
```

同一群的不同发送者各有一行，重复的 `chat_id` 是正常的。字段用途：

| 字段 | 含义 | 配置到哪里 |
|---|---|---|
| `app` | 本地应用别名，如 personal | `routes.app`、`delivery.app` |
| `app_id` | 飞书应用 ID | 核对是否对应正确机器人；来自应用凭证 |
| `chat_id` | 群或私聊会话 ID，一般以 oc_ 开头 | 群分流 `routes.chat_id`；发到会话时 `receive_id_type = "chat_id"` |
| `chat_type` | group 群聊／p2p 私聊 | 可选 `routes.chat_type` |
| `sender_open_id` | 发送者在此应用下的 open_id，一般以 ou_ 开头 | 私聊发送 `receive_id_type = "open_id"`；`allowed_sender_ids` |
| `sender_id` | 与 sender_open_id 相同的兼容字段 | 优先使用清楚命名的 sender_open_id |
| `user_id` | 飞书 user_id；事件未提供时为 null | 用于识别来源；本版发送用 chat_id／open_id，不能填入 open_id 过滤列表 |
| `first_seen`／`last_seen` | Unix 秒时间戳 | 判断最近哪条测试消息对应这个来源 |
| `message_count` | 观察到的事件数量，重放也可能计数 | 参考活跃度，不是原文去重计数 |

open_id 与应用相关；不要把机器人 A 查到的 open_id 配给机器人 B。
群发送用群的 `chat_id`；私聊可用用户的 `sender_open_id`，也可明确发送到已有私聊 `chat_id`。
获取群／用户 ID 无需每条消息都打印机器人信息。

如果多个群难以区分，临时开启发现模式，在目标群发送测试文本后查日志：

```bash
uv run python -m app.feishu_cli discover --app personal --seconds 600
uv run python -m app.feishu_cli logs --role collector --lines 100
uv run python -m app.feishu_cli discover --app personal --seconds 0
```

`event=feishu.source` 包含会话、发送者、message_id、消息类型、mentions、路由结果，不包含正文。
`mentioned_bot=unknown` 表示未查询机器人 open_id；默认不要求 @，无需额外请求身份接口。
如果配置 `require_at = true`，才查询机器人身份并判断是否 @ 本机器人；查不到身份时严格过滤。
CLI 发现窗口最长 3600 秒，默认 600 秒，到期自动关闭；重启、无关 TOML 修改不会续期。
CLI 的应用级开关优先于全局 TOML 发现开关。发现日志每个采集连接最多每分钟 60 条。
新会话首次发现输出一次 INFO；来源记录默认保留 90 天，最多 10000 条，超出会清理较旧记录。

## 5. 配置分流与发送目的地

新增业务的完整配置示例、热更新确认和本地／Docker 重启规则见[扩展指南](扩展指南.md)。
复用现有机器人与 markdown_collect 的 routes／pipelines 扩展通常不需要手动重启。

把清单中的真实 ID 填入 TOML。以下为新增路由，放在 `[[pipelines]]` 之前便于阅读：

```toml
[[routes]]
id = "ideas-group"
app = "personal"
chat_id = "oc_实际群聊ID"
pipeline = "inspiration"
require_at = false
allowed_sender_ids = []
```

如果只允许自己，`allowed_sender_ids = ["ou_实际发送者open_id"]`。
指定会话优先于指定类型；未匹配任何路由才进入应用的 `default_pipeline`。
命中路由但被发送者或 @ 条件过滤的消息不会回落到默认流程。
新增机器人时增加一个 `[[apps]]`，使用独立密钥环境变量名和稳定别名。
增加新群复用已有流程只加路由；不同提示词／模型／输出位置则新增流程与可选 AI profile。
当前已实现的处理器为 `markdown_collect`；新增业务处理器需要写代码并明确注册，不支持任意动态导入。

默认多个来源共享同一流程的一份输入文档。若需要按来源拆开，修改该流程已有字段：

```toml
input_path = "data/feishu/{app_id}/{chat_id}/pending.md"
```

每个展开后的路径是一个独立实例；两条流程不能共享一个输入文件。
输入支持 `{app_id}`、`{chat_id}`、`{pipeline_id}`；输出还支持 `{date}`、`{run_id}`。
修改输入路径后，旧文件保留但不再被该流程定时处理；手动迁移文件时先停止写入进程并备份。

在对应流程最后加发送配置：

```toml
[pipelines.delivery]
app = "personal"
receive_id_type = "chat_id"
receive_id = "oc_实际结果接收群ID"
```

发给个人时把类型改为 `open_id`，填同一应用查出的 `sender_open_id`。
不配置 delivery 则只保存 Markdown。完成 AI 后先保存结果，再发送到指定目的地；
发送失败重试已生成结果，不再次请求 AI。长结果按 UTF-8 字节分段发送。

## 6. 无需等到凌晨：手动执行、重试与删除

```bash
uv run python -m app.feishu_cli validate
uv run python -m app.feishu_cli status
# 先看输入路径和 AI 状态，不请求 AI
uv run python -m app.feishu_cli process inspiration
# 确认配置后真正请求 AI，可能同时向配置的目的地发送消息
uv run python -m app.feishu_cli process inspiration --execute
```

有多个来源实例时，从 `status.streams` 复制实例 ID：

```bash
uv run python -m app.feishu_cli process inspiration --stream-id 复制的实例ID
uv run python -m app.feishu_cli process inspiration --stream-id 复制的实例ID --execute
# 一次调度检查，并消费至多一项到期任务；这不是强制提交指定文档
uv run python -m app.feishu_cli worker --once
```

任务状态为 pending／processing／succeeded／failed／skipped／cancelled。
失败先看 `last_error` 与文件日志；自动重试默认间隔 30 秒、最多 3 次。
只重试同一次失败任务：

```bash
uv run python -m app.feishu_cli retry 任务ID
uv run python -m app.feishu_cli retry 任务ID --execute
```

成功任务再次整理用 `process --execute`；`retry` 只恢复失败任务。
已生成结果的任务即使原文随后删除，也会继续保存／投递这份结果；尚未请求 AI 的任务在执行前
核对原文和批次，已删除则取消。已经发出的请求无法撤回。
原文仍在且非空，下一天会处理全文，包括此前多天积累的内容；不是只处理当日新增行。
用户自行删除原文后，定时任务跳过；新消息自动创建新文档，不恢复上一批内容。
不要删除内部批次与消息标识；它们为去重和崩溃恢复服务，提交 AI 前会移除。
首次接管旧 Markdown 会保留原内容，下一条新消息登记实例并追加完整日期及来源。

调度启动后可补当天已过 01:00 的任务，不追补所有历史日期。
01:00 后才创建的新批次不补当天任务；在线把执行时间改到已过时刻也不立即补跑，手动执行即可。
快照成功后清除；没有请求 AI 的失效批次和超过 7 天快照按维护清理，已完成任务元数据默认保留 90 天。
任务完成前保留恢复所需生成结果；因此删除原文不等于删除任务结果、备份或外部服务已收到的内容。

## 7. 热读取、日志与开发调优

TOML 和提示词通过文件修改检测加载：消息到来以及后台轮询时检查，默认约 1 秒。
不是每次都重新解析；任何字段／提示词校验失败，整份修改被拒绝，继续用上个有效版本。
首次启动没有有效版本时直接退出。`validate` 可在启动前离线校验。

| 变化 | 生效方式 |
|---|---|
| 路由、流程启停、模型／Base URL／参数、提示词、结果路径、发送目的地 | 下一事件或新任务生效；已有任务保持提交时的非密钥配置 |
| 新增／删除／禁用应用，凭证环境变量引用或飞书域名 | 只重建对应应用连接 |
| 日志级别、保留天数／容量、发现模式 | 后台加载生效 |
| runtime 全部字段、根目录、数据库、log_dir | 需要重启；运行中修改会拒绝整份配置 |
| 环境变量实际值、`.env` 内容 | 重启进程；已有任务不存密钥，运行时读取所引用的密钥 |

已有任务的 AI Base URL／提示词被固定，修改后需新建任务才能使用新配置。
如果换了应用身份，旧发送任务不会自动改用另一个机器人；查清旧任务状态再重新提交。

常用调优：

| 参数 | 默认 | 开发建议／代价 |
|---|---|---|
| runtime.poll_seconds | 1 | 降低会更快落盘／检查任务，但增加数据库查询；修改需重启 |
| runtime.retry_seconds／max_attempts | 30／3 | 本地替身测试可缩短；真实服务避免短时间密集重试；修改需重启 |
| ai_profiles.*.timeout_seconds | 120 | 按服务实际延迟设置；客户端不隐式重试，由任务管理 |
| ai_profiles.*.max_input_bytes | 500000 | UTF-8 字节预检查，包含提示词；不代表模型 token 上限，超限需拆文档或换模型 |
| observability.level | INFO | 临时 DEBUG 查看逐条元数据，不输出正文；恢复 INFO 减少噪声 |
| observability.summary_interval_seconds | 300 | 有采集活动才输出汇总 |
| observability.console | false | 本地可 true，同一正式日志追加输出到 stderr |

正式日志位于 `data/logs/feishu/{collector,processor,cli}/`，同时按文件 10 MB、角色总量 100 MB、
最多约 7 天限制。容量达到上限可能更早删旧日志；启动及每小时维护，即使无消息也会清理。
同类错误 60 秒内抑制重复，之后附带被抑制次数。只清理此目录下本模块命名的日志。

```bash
uv run python -m app.feishu_cli logs --role collector --lines 100
uv run python -m app.feishu_cli logs --role processor --lines 100
uv run python -m app.feishu_cli logs --role cli --lines 100
```

Docker 两个新角色使用 `logging.driver: none`，不再额外积累 Docker stdout 日志；
因此查询正式文件日志，不使用 `docker logs`。若自行改成 Docker local 驱动，
其容量上限不能替代时间保留策略。参考 [Docker 日志配置](https://docs.docker.com/engine/logging/configure/)。

## 8. 本地验收后才做 Docker

先完成：模拟采集 → 查询来源 → 手动预览 → 本地真实消息落盘 → 小文档 AI 处理 → 结果保存／投递。
AI 与飞书真实服务费用、限流和权限由实际环境验证；自动测试不调用它们。

开发机最后才需要构建检查（Docker 已运行时）：

```bash
./scripts/test.sh all
docker build -t myservice-feishu-local .
```

生产部署沿用仓库发布流程，拉取 GitHub Actions 发布的 Docker Hub 镜像，不在部署机编译。
当前工作树代码必须先经发布流程生成包含本功能的新镜像；旧 latest 不代表已经包含这些修改。

将 TOML 与 prompts 复制到部署目录的 `config/`，数据放在持久化目录。
生产 `.env` 设置 `FEISHU_CONFIG_PATH=config/feishu.toml`，需要时设置
`MYSERVICE_CONFIG_DIR=/你的配置目录`、`MYSERVICE_DATA_DIR=/你的数据目录`。
TOML `root_dir = ".."` 在容器内解析为 `/app`；数据路径应是 `data/...` 或 `/app/data/...`。
不要把开发机 `/Users/...` 写进容器配置。配置目录挂载只读，宿主机可修改；整个目录挂载支持编辑器原子替换。

生产移除 SQLite 的 `FEISHU_STATE_DATABASE_URL`，留空沿用 POSTGRES_*。
使用外部数据库时先核对宿主机、库名、端口和访问范围。迁移前备份数据库及灵感文件，
按现有部署手册检查 `alembic current`；新 head 为 `20261002_feishu`。
`migrate` 服务负责迁移，两个 worker 都等待迁移成功；不要对已有库运行 init-local 或全量 create_all。

```bash
# 仅校验 Compose，不创建容器
docker compose --profile inspiration --profile inspiration-ai config --quiet
# 确认新版本已发布、备份完成后，执行正式部署
docker compose --profile inspiration --profile inspiration-ai pull
docker compose --profile inspiration --profile inspiration-ai up -d --wait
```

外部 PostgreSQL 版本为每条命令增加 `-f docker-compose.external-postgres.yml`。
只需要采集就只启用 `inspiration`；AI 调度角色使用 `inspiration-ai`。
不用重建镜像即可修改 TOML／提示词；更改 `.env` 或 runtime 参数需按相应服务重启／重建容器。

容器内查询，不另开采集连接：

```bash
docker compose exec feishu-inspiration python -m app.feishu_cli sources --app personal
docker compose exec feishu-inspiration python -m app.feishu_cli discover --app personal --seconds 600
docker compose exec feishu-inspiration python -m app.feishu_cli logs --role collector --lines 100
docker compose exec inspiration-processing python -m app.feishu_cli status
docker compose exec inspiration-processing python -m app.feishu_cli logs --role processor --lines 100
docker compose exec inspiration-processing python -m app.feishu_cli process inspiration
```

采集与整理共用 PostgreSQL 和挂载数据；不要让本地与容器同时对同一个应用建立采集连接。
共享目录内的角色锁会拒绝第二份同角色进程，但不同机器／不同挂载目录无法靠该锁互斥。
自动部署没有主动连接飞书的健康检查，容器运行状态不等于端到端采集成功，需按下面验收。

## 9. 验收与排查

| 验收／现象 | 预期与下一步 |
|---|---|
| 新群／私聊发一条唯一文本 | 清单出现对应 ID；原文出现完整日期、发送者和会话 ID；回执在落盘之后 |
| 重启后收到相同事件 | 持久化消息 ID 防止重复追加；本地闭环演示验证该场景 |
| 手动 AI 执行 | 独立结果 Markdown；配置 delivery 时同一份结果发到指定目的地 |
| 整理成功后删掉原文 | 后续无输入跳过；新消息开启新批次，旧批次不得恢复 |
| 清单没有目标来源 | 先确认在同一机器人对应的群／私聊发了新消息；查看 collector 日志和 app 别名 |
| 清单有来源却没落盘 | 看路由／过滤／文本类型、写入权限、是否同一路径被其他流程占用 |
| 有原文但没有 AI | 检查 ai.enabled、模型／密钥、执行时间与批次创建时间；用 process 预览和 status |
| config.rejected | 整份热更新拒绝，旧版继续运行；validate 校验，runtime／日志目录变化需重启 |
| state_schema_missing／ProgrammingError／42P01 | 当前状态库缺表；SQLite 执行 init-local；PostgreSQL 先备份并核对目标库与 migrate 结果，不重置库 |
| OperationalError | 状态库连接异常；核对隔离／生产目标与服务可用性，输出默认不暴露连接串 |
| BlockingIOError | 同角色已有进程持锁；关闭重复启动，不删除正在使用的锁文件 |
| ai_input_too_large | 当前文档超字节预算；整理输入后重新 process，失败任务无快照不能 retry |
| ai_http_401／feishu_app_changed | 修正密钥／应用身份并重启；旧任务目的地保持原应用，不自动换机器人 |
| delivery 已失败但 output_saved=true | 结果已保存，修复发送问题后 retry；不会再次调用 AI |
| docker logs 无输出 | 本模块使用 none 日志驱动；用 app.feishu_cli logs 或读取挂载日志目录 |

发现输入路径指向用户不期望的目录、配置引用不正确、生产目标不确定时，先停止对应角色并校验，
不要执行 AI、发送消息、迁移或删除数据。保留数据库与 `data/` 备份；不要直接 downgrade 新迁移，
它会删除本功能的五张状态表。关闭 AI 可停整理角色或将 ai.enabled 改为 false；已生成的投递任务仍可继续恢复。

飞书发送使用稳定 uuid 降低响应丢失后的重复投递，超出服务端去重有效期仍可能重复；
外部服务已处理但本地未保存阶段结果的崩溃窗口，也不能保证 AI 费用只发生一次。
服务承诺的是持久化恢复与分阶段重试，不声称外部调用绝对恰好一次。
